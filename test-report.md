**Объект:** набор из пяти страниц — хаб `index.html` и четыре лендинга (`zerno-coffee`, `lingua-school`, `pixel-kids`, `wander-travel`). Разбор кейсов и этапы проверки — в `showcase.html`, сводка — в `review.html`.
**Как проверялось:** Chromium (Playwright) на пяти разрешениях по семи ширинам — 1440 / 1280 / 1024 / 900 / 768 / 480 / 390 / 320 px, с эмуляцией `prefers-reduced-motion: reduce` и принудительно раскрытыми появлениями, чтобы снимок совпадал с тем, что увидит человек.
**Позиция:** я намеренно искал, за что зацепиться. Ниже отдельно — что нашлось и исправлено, и что осталось слабым.

### 2.2a Ввод в формы: телефон и почта (нашлось по замечанию владельца)

Замечание: «при вводе номера телефона не стоит ограничение по символам» и «проверить логику ввода почты». Замечание подтвердилось: поля принимали что угодно и любой длины, а форма стояла с `novalidate` — то есть браузерная проверка была отключена и ни один формат не проверялся.

**Телефон** (zerno, pixel-kids — «+7 (___) ___-__-__»):

| Действие | Было | Стало |
|---|---|---|
| Набрать 22 цифры подряд | сохранялись все | 11 цифр, лишние не печатаются: `+7 (916) 123-45-67` |
| Набрать `89161234567` | как есть | `+7 (916) 123-45-67` |
| Ввести буквы | буквы оставались | не вводятся |
| Вставить «+7 916 123-45-67 доб. 123» | всё как вставили | `+7 (916) 123-45-67` |
| Программная подстановка 40 цифр | проходила | обрезается до 11 цифр |
| Отправить номер из 5 цифр | заявка уходила | подсветка поля + «Проверьте номер телефона: нужно 11 цифр…» |

Иностранный номер (12 цифр с кодом 44…) принимается в формате `+44207946095`, больше 15 цифр не вводится.

**Телефон или Telegram** (lingua): то же поле плюс режим ника — `@my_nick` проходит, `@ab` (короче четырёх знаков) и `@my_nick!?` нет; лишние символы в нике отбрасываются.

**Почта** (wander): принимается `ivan@mail.ru`, `IVAN.PETROV@MAIL.CO.UK`, `ivan+dev@mail.ru`, `ivan_dev@mail-1.ru`. Отклоняются `ivan`, `ivan@`, `ivan@mail`, `ivan@mail.c`, `ivan@mail.ru.`, `.ivan@mail.ru`, `ivan.@mail.ru`, `ivan..petrov@mail.ru`, `ivan@mail..ru`, `ivan@-mail.ru`, `ivan@mail-.ru`. Пробелы внутри адреса вырезаются, длина ограничена 254 символами (вставка 300 символов обрезается, скриптом тоже не пролезть).

**Дополнительно, по ходу проверки нашёлся настоящий баг:** при наборе номера по одной цифре каретка прыгала, и цифры перемешивались — «9161234567» превращалось в «+7 (161) 234-56-79». Причина: после переформатирования курсор ставился по числу цифр слева, и следующая цифра попадала в середину. Исправлено: каретка идёт за последней введённой цифрой, при удалении в середине — на месте. Проверено повторно: и набор по одной цифре, и вставка, и правка в середине дают верный номер.

Всего по полям добавлено: ограничения длины (телефон 18, почта 254, имя 80, комментарий 600), `maxlength` на всех полях, `spellcheck="false"` и `autocapitalize="off"` для почты и ника, `aria-invalid` на полях с ошибкой. Поверх разметки — проверка на сервере браузера, поэтому ограничение нельзя обойти ни вставкой, ни скриптом. Цвета подсказок об ошибке тоже проверены по контрасту: 5.5–11.8 при норме 4.5; у «Зерна» заодно затемнены текст подсказки (было 4.15) и сообщение об успешной отправке (4.11).

## 3. Что осталось слабым (честно)

1. **Вес фотографий — 3.3 MB, JPEG без адаптивных версий.** На телефоне грузятся те же файлы, что и на десктопе: `wander-hero.jpg` 292 KB, `coffee-roaster.jpg` 280 KB, `coffee-latte.jpg` 232 KB. Это главное место, где «продакшн» пока не дотягивает. Лечится либо двумя размерами в `srcset`, либо переводом в WebP — по весу примерно вдвое.
2. **Шрифты: 416 KB в 17 файлах.** Кэшируются, но при первом заходе это заметная доля загрузки. Можно оставить 6–8 файлов вместо 17.
3. **Нет живого адреса.** Все проверки сделаны локально; Lighthouse на реальном хостинге (сеть, кэш, HTTP/2) не проводился. Внутренние цифры (LCP 72–136 мс, сдвиг вёрстки ≈ 0) получены на локальных файлах и на хостинге будут хуже — там их и надо мерить.
4. **OG-теги в хабе отсутствуют** (в разборе кейсов есть). При отправке ссылки в Telegram или WhatsApp карточка будет без заголовка и картинки — нужен абсолютный адрес, поэтому делается при публикации на хостинге.
5. **Разбор кейсов есть, но общий.** В `showcase.html` описано, что требовалось и как проверялось, — по каждому проекту один блок. Отдельной страницы с хронологией дефектов по каждому лендингу нет; глубина — на уровне отчёта, а не дневника.
6. **Не проверялись:** Safari и iOS, реальные устройства, отключённые веб-шрифты, печать (стилей для печати нет). В песочнице доступен только Chromium.

## 4. Вердикт

Критических дефектов нет. Страницы выдерживают проверку как набор: одинаково аккуратно ведут себя на семи ширинах, не ломаются при отключённой анимации, не мешают клавиатуре и скринридеру, дают читаемый контраст, держат типографскую шкалу, ограничивают и проверяют ввод в формах и не врут в текстах.

Чтобы это называлось «продакшн», остаются две вещи, и обе — не про качество вёрстки: адаптивные фотографии и живой адрес с отчётом Lighthouse. Первое закрывается за вечер, второе — публикацией на хостинге.

## 5. Как это повторить

Переполнение, консоль и битые запросы ловятся скриптом — двадцать строк, без зависимостей кроме Playwright:

```python
import os
from playwright.sync_api import sync_playwright

PAGES = ["index.html", "showcase.html", "zerno-coffee.html",
         "lingua-school.html", "pixel-kids.html", "wander-travel.html"]
WIDTHS = [1440, 1280, 1024, 900, 768, 480, 390]

with sync_playwright() as p:
    browser = p.chromium.launch()
    for width in WIDTHS:
        page = browser.new_page(viewport={"width": width, "height": 900})
        errors = []
        page.on("console", lambda m: m.type == "error" and errors.append(m.text))
        page.on("requestfailed", lambda r: errors.append("нет файла: " + r.url.split("/")[-1]))
        for name in PAGES:
            page.goto("file://" + os.path.abspath(name))
            page.evaluate("window.scrollTo(0, document.body.scrollHeight)")
            page.wait_for_timeout(250)
            over = page.evaluate("document.documentElement.scrollWidth"
                                 " - document.documentElement.clientWidth")
            if over:
                print(f"{name} @{width}px: шире экрана на {over}px")
        for text in errors:
            print(f"@{width}px: {text}")
```

Остальное глазами и руками: заголовки по уровням и `alt` у картинок; контраст по значениям из CSS через формулу WCAG; Tab по всей странице — фокус должен быть виден на каждом шаге; формы — пустая отправка, мусор в поле, нормальная отправка; отключённая анимация — через `prefers-reduced-motion` в DevTools.

Снимки текущего состояния: `review/` (по 2 файла на страницу, десктоп и мобильный) в разборе `review.html`.
